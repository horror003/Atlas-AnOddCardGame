# 项目交接说明 · 天光墟纪事 Atlas

> 用途：供新的 AI 会话或新的开发者快速接续本项目。最后更新：2026-10-21。

## 一、项目概况

- 项目：本地热座（同机轮流操作）卡牌对战游戏《天光墟纪事 Atlas》，当前为 MVP。
- 引擎：Godot 4.7（Forward+），语言 GDScript，**数据驱动架构**。
- 代码与数据分离：规则引擎（`game.gd`）不依赖任何 UI 节点，UI（`main.gd`）只调用 `ui_*` 方法并读取公开状态。
- 逻辑视口 1280×800，开启 stretch（`canvas_items` + `expand`），所以逻辑高度恒为 800。

## 二、快速开始

启动方式：用 Godot 打开 `d:\Atlas\project.godot`，主场景是 `scenes/launcher.tscn`（启动器，可选择「开始对战」或「数据编辑器」）。

命令行验证（Windows PowerShell）：

```powershell
$godot = "D:\SteamLibrary\steamapps\common\Godot Engine\godot.windows.opt.tools.64.exe"

# 1. 编译检查（脚本解析/类型错误）
& $godot --headless --editor --path "d:\Atlas" --quit

# 2. 冒烟运行
& $godot --headless --path "d:\Atlas" --quit-after 40

# 3. 单独运行某个场景
& $godot --headless --path "d:\Atlas" res://scenes/main.tscn --quit-after 60
& $godot --headless --path "d:\Atlas" res://scenes/editor.tscn --quit-after 60
```

注意：

- 项目把 GDScript 警告当错误处理，**编译通过才算完成**。
- headless 下字体尺寸量测不准确，UI 布局问题必须用真实窗口验证：
  `& $godot --path "d:\Atlas" --resolution 1280x800 --script "d:\Atlas\probe_xxx.gd"`

## 四、当前状态（已完成）

1. 项目基础、牌堆系统、回合状态机（判定 → 摸牌 → 出牌 → 弃牌）、基础出牌、防御响应、技能、特殊事件、濒死与胜负、热座流程。
2. 通用被动系统：`hook` + `conditions` + `effect` + `max_uses_per_turn`，装备、属性、装备组合共用，**新增效果只改 JSON**。
3. 装备组合（`combos.json`）：同时装备 `parts` 中全部装备自动激活，组合被动与装备/属性被动叠加。
4. **职业系统已改为属性系统**：
   - `professions.json` 已删除，改为 `attributes.json`（两派系 + 8 属性）。
   - 派系一：时间 · 生命 · 臆想 · 粒子；派系二：空间 · 冥暗 · 混沌 · 信息。
   - 每个角色从两派系**各选 1 个属性**（`attribute_ids`，共 16 种组合）。
   - 旧职业机制（守御士生命+4、拓荒者装备豁免、撰文人首攻+1、礼乐人魔法回血）**已全部移除**。
   - 属性具体效果尚未定义，`passive` 字段已预留。
5. 词条符号规范（六类，禁止混用）：| 类型     | 符号 | 示例         |
   | -------- | ---- | ------------ |
   | 卡牌名   | 【】 | 【普通攻击】 |
   | 技能名   | 〖〗 | 〖奋击〗     |
   | 状态名   | 「」 | 「燃烧」     |

6. UI 修复：日志区宽度、整页滚轮冒泡（`NoWheelScroll` 吞滚轮）、玩家面板文字压缩（`RichTextLabel.fit_content = true`）、状态点击详情、弃牌在手牌区直接选择、玩家面板外层滚动容器保证按钮可访问。

## 五、数据规范速查

七类文件：`cards.json`、`skills.json`、`statuses.json`、`events.json`、`attributes.json`、`characters.json`、`combos.json`。
字段与示例的完整说明见 `docs/数据JSON编写说明.md`（含附录「动作类型速查表」）。

关键点：

- 目标类型多目标（`all_players/all_enemies/all_allies/all_others`）无需选目标，自动依次结算。
- 动作类型 11 种：`deal_damage`、`heal`、`draw_cards`、`lose_hp`、`add_status`、`remove_status`、`discard_cards`、`discard_target_pick`、`random_discard`、`trigger_event`、`retrieve_defense`。
- `lose_hp` = 直接扣血，不受防御/装备影响。
- 多段伤害会拆成独立伤害实例，逐个响应，不要合并结算。
- 规则：摸牌阶段手牌不足摸牌值（默认 5）补至该值；弃牌阶段超过存牌值（默认 3）弃至该值。
- 角色 `attribute_ids` 必须两派系各 1 个，编辑器保存时会校验。

## 六、编码约定与已知陷阱

- 规则逻辑只放 `game.gd`，界面逻辑只放 `main.gd`；不要在 UI 里写规则。
- 不要用 `:=` 推断返回 `Variant` 的函数的类型（会被警告当错误拦截），用显式类型。
- 普通 `Control` 不是 `Container`，不会给子控件排版，子控件需 `PRESET_FULL_RECT` 锚点。
- `ScrollContainer` 内 `SIZE_EXPAND_FILL` 可能失效，需要 `custom_minimum_size`。
- GDScript 不能用 `super()` 调用 C++ 虚函数（外层的 `NoWheelScroll` 直接 `pass` 吞滚轮即可）。
- `RichTextLabel` 在纵向容器里用 `fit_content = true`，不用 `EXPAND_FILL`，否则会挤压同面板的信息行/技能行。
- 异步流程（如洞悉弃牌）恢复点必须用显式上下文标记，禁止用 `mode` 推断。
- 修改数据后必须跑编译 + 冒烟；涉及 UI 的改动要用真实窗口验证。

## 八、远程工作方式

当前的 TraeCode IDE 会话**无法被手机接管**，TRAE 移动端只能连接 TraeWork 桌面版。
在手机上远程推进本项目的方式：

1. 手机安装 TRAE，登录与电脑相同的手机号。
2. 电脑打开 TraeWork 桌面版 → 设置 > TRAE 移动端 → 打开「允许 TRAE 移动端控制当前设备」。
3. 手机端选择运行环境「电脑」→ 目录选 `d:\Atlas` → 用 Code 模式下发任务。
4. 建议开启「保持电脑处于唤醒状态」。

任务在电脑本地执行，产物直接写入本目录；但属于**新会话**，需要先读本文件了解上下文。
