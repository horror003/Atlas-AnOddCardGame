# 移动端移植交接文档 · 天光墟纪事 Atlas

> 用途：把「v0.1.1-alpha」移植到移动端（Android 优先，iOS 后续）这一新任务的独立交接材料。
> 基线版本：**v0.1.1-alpha**（提交 `b48da7d`，Release：`https://github.com/horror003/Atlas-AnOddCardGame/releases/tag/v0.1.1-alpha`）
> 编写日期：2026-10-24。配套阅读：`docs/项目交接说明.md`（通用工程约定）、`docs/数据JSON编写说明.md`（数据规范）、`游戏玩法规则文档.md`（规则）。

## 一、任务目标（明确范围）

**做**：把 `scenes/main.tscn`（对战界面）移植到移动端，可完整打完一局热座对战。

**不做**（保持桌面专属）：

- `scenes/editor.tscn` 数据编辑器（`scripts/editor.gd`，31 KB）——移动端不需要，也不建议移植。
- 开发者菜单 `scripts/dev_menu.gd`（仅 `OS.is_debug_build()` 时创建），移动端可保留但**不为其投入适配成本**；注意 F12 在触屏上不可达，如需保留要加一个显式按钮入口。
- 规则引擎 `scripts/game.gd`：**本次任务不应修改**。它不依赖任何 UI 节点，输入与渲染的差异全部在 UI 层解决。

**验收口径**：横屏手机上一次完整对局（选人 → 判定 → 摸牌 → 出牌 → 弃牌 → 胜负）无卡死、无不可触达的操作、无文字截断。

## 四、移动端差异清单（逐项现状 → 需要做的事）

### 4.1 输入（最高优先级）

| 现状 | 问题 | 建议 |
| --- | --- | --- |
| 右键取消选目标（`main.gd` `_input()`，第 1104-1105 行） | 触屏没有右键 | 三选一并保留桌面路径：① 复用已有 `cancel_target_btn`（第 106 行）并在移动端放大常驻；② Android 返回键映射为取消（`_notification(NOTIFICATION_WM_GO_BACK_REQUEST)` 或 `KEY_ESCAPE`）；③ 长按空白处取消 |
| `F12` 打开开发者菜单 | 触屏不可达 | 移动端忽略；若需保留，走顶栏按钮（`dev_btn`） |
| `tooltip_text` 悬停提示（4 处） | 触屏无 hover，技能/装备说明看不到 | 改为长按（`InputEventScreenTouch` 计时 400-500ms）弹出已有的 `info_popup` 弹层 |
| 富文本 `meta_clicked` 状态链接（第 238 行附近） | 可点，但字号与命中区域偏小 | 触摸命中的是文字本身，建议增大状态行字号、必要时行内留白加大 |
| 拖动出牌（Godot 拖放） | 触摸 + 页面滚动会互相争抢 | 见 4.2 |

触摸模拟方案（`project.godot` 需新增）：

```ini
[input_devices]

pointing/emulate_mouse_from_touch=true
pointing/emulate_touch_from_mouse=true   # 仅便于桌面用鼠标调试，发布前可关
```

开启后触摸会合成鼠标事件，现有拖放与按钮逻辑可直接复用，但**长按与拖拽的区分**仍要自己处理。

### 4.2 拖放与滚动冲突

手牌区是 `HFlowContainer` 套在 `ScrollContainer` 里（第 95-96 行）。触屏上「按住往上滑」既可能是滚动手牌区，也可能是拖牌到玩家面板。建议：

1. 手牌数 ≤ 一屏时禁用该区域滚动（现在 6 张以内本来就不滚动），消除歧义；
2. 需要滚动时，用「长按 300ms 进入拖拽」区分，或在拖拽期间临时 `ScrollContainer.vertical_scroll_mode = DISABLED`；
3. 拖拽预览（`set_drag_preview`）在手机上跟手性差，可改为「先点选卡牌 → 再点目标面板」的两段式，作为触屏主路径（规则层已有 `SELECT_TARGET` 模式，改动集中在 UI）。

> 两段式点击是移动端最稳的交互，建议作为**默认路径**，拖拽作为桌面保留。

### 4.3 布局与分辨率

- 当前 `1280×800` + `keep_height`：18:9 / 19.5:9 手机上横向会被裁切，必须重新定策略。
- 建议：**锁定横屏**，基准 `1280×720`（16:9），`stretch/mode="canvas_items"`、`aspect="expand"`，让多出来的横向空间由 `HFlowContainer`（手牌）和日志区吸收。
- 安全区（刘海/挖孔/手势条）：`DisplayServer.get_display_safe_area()` 换算成逻辑坐标后给根容器加边距，不要硬编码。
- `ROOT_MIN_HEIGHT=760`、`PLAYER_PANEL_HEIGHT=156`、`SIDEBAR_WIDTH=262` 这些常量是按 800 高算的，720 基准下要成比例调整（不要逐处改，集中到一两个缩放系数里）。
- 竖屏不做支持：牌桌信息密度决定了必须横屏；`project.godot` 设 `display/window/handheld/orientation="landscape"`。

### 4.4 点击目标尺寸

- 现有按钮 `MENU_BTN_SIZE=110×32`、`ACTION_BTN_HEIGHT=36`，在手机上偏小。
- 目标：所有可点元素短边 ≥ 44dp（在 1280 基准、约 400dpi 手机换算下来 ≈ 56-64 逻辑像素）。
- 建议在 `ui_theme.gd` 增加统一的 `touch_scale()` 系数，移动端所有 `custom_minimum_size` 乘该系数，桌面保持 1.0。

### 4.5 渲染与性能

- `Forward+` → 移动端改为 **Mobile** 渲染器（`config/features` 与项目设置里改，或使用单独 export preset 覆盖）。
- 检查是否有后处理/高分辨率纹理；本项目 UI 为主、无 3D，性能压力主要在**大量 `RichTextLabel` 与每帧重建的 UI**（`main.gd` 的 `_refresh()` 全量重建面板与手牌）。
- 手机低端机重点观察：日志区文本增长、15 张手牌时的换行重排（`_fit_hand_cards` 每次 `_refresh` 后延迟重算一次，注意别形成抖动循环）。

### 4.6 字体与包体

- 中文字体是否内嵌需先确认（`ui_theme.gd` 的 `make_theme()`）；Android 依赖系统字体有一定风险（不同 ROM 字体差异、缺字）。
- 建议内嵌一份中文字体子集，体积与字形覆盖取平衡；`【】〖〗「」『』《》〈〉` 这些符号必须确认在子集内。
- 包体基线先测：APK 与 AAB 各打一次，记录未压缩大小。

### 4.7 生命周期

- Android 切后台再回来：`NOTIFICATION_APPLICATION_FOCUS_OUT/IN`、`NOTIFICATION_WM_WINDOW_FOCUS_OUT`，确认热座流程与弹层状态不丢（`pending` 上下文在 `game.gd` 内存中，正常不会丢，但 UI 需刷新）。
- 来电/锁屏导致的暂停不应触发「回合跳过」等逻辑（本作无实时计时，风险低，验证一次即可）。

## 五、分阶段计划

### P0 · 打通导出链路（先让空壳跑起来）

1. Godot 编辑器 → `Editor` → `Manage Export Templates` → 下载 4.7.2 模板。
2. `Project` → `Export` → 新增 **Android** preset（`export_presets.cfg` 会生成在项目根，注意 `release/` 已在 `.gitignore`，但 `export_presets.cfg` 需要提交）。
3. 配置 Android SDK / JDK（Godot 4.7 要求 JDK 17 + Android SDK Build-Tools），在编辑器设置里指定路径。
4. 导出 debug APK，装到真机，确认 `launcher.tscn` 能启动、能进 `main.tscn`。
5. 记录：包体、启动耗时、首帧是否黑屏。

**验收**：真机能进入对战界面，日志与手牌区可见。

### P1 · 输入与交互（决定能否玩）

1. 开启 `emulate_mouse_from_touch`，跑一局，列出所有「点不到/点错」的操作点。
2. 取消选目标：接 Android 返回键 + 常驻取消按钮。
3. tooltip 改长按弹 `info_popup`。
4. 出牌改两段式（点牌 → 点目标），拖拽保留给桌面。
5. 手牌区滚动与拖拽解耦（4.2）。

**验收**：全程不依赖右键、不依赖悬停、不依赖键盘。

### P2 · 布局适配

1. 横屏锁定 + `1280×720` 基准 + `expand`。
2. 安全区边距。
3. 所有可点元素 ≥ 44dp；字号整体放大一档。
4. 弹层（选人、技能选牌、弃牌选择、事件展示、终局）全屏化并处理返回键。
5. 手牌换行在窄高屏幕上的表现（`_hand_layout` / `_fit_hand_cards`）。

**验收**：16:9、19.5:9、4:3 三种比例下无截断、无重叠、无不可达元素。

### P3 · 性能与打磨

1. Mobile 渲染器；`_refresh()` 在低端机上是否掉帧，必要时做增量刷新（先测量再优化）。
2. 字体子集与包体。
3. 切后台/回前台状态验证。
4. 触感反馈（可选）：按钮/出牌 `Input.vibrate_handheld()`。

**验收**：中端机稳定 60fps（UI 场景），无明显卡顿与内存增长。

### P4 · 打包发布

1. 生成 keystore（**密钥与密码不入库**），配置 release preset。
2. `version/code` 与 `version/name` 与游戏版本对应：`0.1.1` / `0.1.1-alpha-mobile`。
3. 先出 AAB 供内测，再决定是否上架。
4. 若随 GitHub Release 分发：APK 作为附件上传（沿用第十节的 API 方式）。

## 八、已知坑（沿用桌面版 + 移动端新增）

桌面版已有（见 `docs/项目交接说明.md` 第六节，务必遵守）：

- 警告当错误；`:=` 推断 `Variant` 会报错，用显式类型。
- GDScript 没有 `Array.join` / `String.join`，拼字符串要手写循环或用 `+`。
- 普通 `Control` 不是 `Container`，子控件需 `PRESET_FULL_RECT`。
- `ScrollContainer` 内 `SIZE_EXPAND_FILL` 可能失效，需 `custom_minimum_size`。
- `RichTextLabel` 在纵向容器用 `fit_content = true`。
- 异步流程恢复点必须用显式上下文标记，禁止用 `mode` 推断。
- 不要用 `String(int)` 构造，用 `str()`。

移动端新增：

- **触摸模拟鼠标会改变事件序列**：同时开着 `emulate_mouse_from_touch` 和自定义 `InputEventScreenTouch` 处理时，注意别把一次触摸算成两次点击。
- 拖放与滚动争抢（4.2），不要指望默认行为。
- 安全区不能硬编码，必须读 `DisplayServer.get_display_safe_area()`。
- Android 返回键默认会退出应用，在「选目标/弹层」状态下必须拦截。
- 导出 preset 变更后 `export_presets.cfg` 会出现在工作区，记得提交，但**keystore 与密码不要入库**（加进 `.gitignore`）。
- `release/` 目录已被忽略，移动端产物建议同样放在 `release/` 下。

## 十、发布与网络限制（重要，交接时必读）

本机网络环境特殊：

- `github.com` **直连被墙**（git push/fetch、gh 的设备码登录都会失败）。
- `api.github.com` **可直连**（`https://api.github.com/rate_limit` 返回 200）。
- git 推送需要走本机系统代理：`git -c http.proxy=http://127.0.0.1:<端口> push`（端口见注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings` 的 `ProxyServer`，会随 IDE 重启变化）。
- 上次发布 v0.1.1-alpha 是通过 REST API 完成的：

```
POST https://api.github.com/repos/horror003/Atlas-AnOddCardGame/releases
Authorization: token <由 git credential fill 取到的令牌>
{ "tag_name": "...", "target_commitish": "<sha>", "name": "...", "body": "...", "prerelease": true }
```

- GitHub 网页端「New release」表单曾连续 3 次报 `tag name is not a valid tag ... target commitish is invalid`，仓库侧确认干净，最终用 API 一次成功。**移动端发版建议直接走 API**，不要在该表单上耗时间。
- `gh` CLI 已安装（`C:\Program Files\GitHub CLI\gh.exe`），但登录不可用；若要用，需自备 fine-grained token 并设 `GH_TOKEN`（gh 只访问 `api.github.com`）。
