## 一、任务目标与范围

**做**：把当前只支持 2 人的对战，扩展为可配置人数的多人对战，至少覆盖：

| 板子 | 人数 | 阵营 | 胜负 |
| --- | --- | --- | --- |
| 双人对决（现有） | 2 | 各自一队 | 对方死亡 |
| 三方混战 | 3 | 各自一队 | 只剩一人存活 |
| 双人组队 | 4 | 2 队 × 2 人 | 一方全队阵亡 |

**不做**：

- 不做联网对战，仍为**本地热座**。
- 不做 AI 玩家。
- 不做 5 人及以上模式（模型需可扩展，但本期不验证）。
- 不重写伤害结算、技能、事件机制；只改「人数/阵营相关的判定」。

**验收口径**：三种板子各完整跑一局（选人 → 判定 → 摸牌 → 出牌 → 弃牌 → 胜负），无卡死、无错误目标、无错误胜负。

## 二、已确认的设计决策

本节为本次需求确认过的口径，实现不得偏离；如需变更，先改本节再改代码。

### 2.1 阵营模型

- `PlayerData` 新增 `team_id`（队伍标识）与 `seat_index`（座位序号）。
- 人数、队伍划分、座次全部由新的**板子配置**（`data/boards.json`）决定，不在代码里写死。
- 座位顺序 = `seat_index` 升序，回合按座位循环推进。
- 2v2 默认采用**交错座位**：座位 0/2 为 A 队，1/3 为 B 队，保证回合在队伍间交替。

### 2.2 胜负判定

- **按队伍结算**：场上只剩 1 支存活队伍时结束，该队获胜。
- 1v1v1 视为「每队 1 人」，因此自然退化为「最后存活者胜」。
- 1v1 保持原行为不变。
- 需要处理**同一次结算中多人同时死亡**（如『天罚』）：先结算完所有目标，再做一次全量队伍存活判定。

### 2.3 濒死救援

- **任意存活玩家均可救援**（含敌方），按座位顺序从濒死者下一位开始询问。
- 现实现 `_open_dying_window()` 已经满足该口径，**本次不需要改**；仅需在多人回归中验证顺序正确。

### 2.4 热座隐私

- **手牌常显，不做交接遮罩**：沿用「只显示当前行动玩家手牌」的现状，切换回合不弹确认层以上的隐私遮罩。
- 其他玩家的手牌**数量**仍公开，内容不进入 UI。

### 2.5 规则缺口口径（已确认，2026-10-26）

| # | 问题 | 确认口径 |
| --- | --- | --- |
| 1 | 2v2「友方」是否含自己 | **包含自己** |
| 2 | 队友陷阱是否可见 | **队友的陷阱内容全部可见**；敌方仍只见数量 |
| 3 | 〖放逐〗等「询问其他存活玩家」的范围 | **所有存活玩家都询问（含敌方）**；询问本身**不影响**技能目标合法性判定 |
| 4 | 是否允许救援敌方濒死角色 | **允许**，任意存活玩家均可救援 |
| 5 | 组队模式座位与顺序 | **座位随机分配、行动顺序随机**（角色随机落座，队伍由座位映射决定） |
| 6 | 开局初始手牌数量 | **等于摸牌数值 `draw_limit`（默认 5 张）**；现有实现误用 `hand_limit`，本次一并修正 |
| 7 | 技能中「其他玩家」的范围 | **默认包含队友**；只有技能描述明确写「敌人 / 敌方」时才排除队友。〖疫医〗保持「场上任意其他玩家」 |

## 四、目标模型设计

### 4.1 板子配置（`data/boards.json`，新建）

```json
{
  "boards": [
    {
      "id": "board_1v1",
      "name": "双人对决",
      "player_count": 2,
      "teams": [
        { "id": "team_a", "name": "队伍A", "seats": [0] },
        { "id": "team_b", "name": "队伍B", "seats": [1] }
      ],
      "default": true
    },
    {
      "id": "board_1v1v1",
      "name": "三方混战",
      "player_count": 3,
      "teams": [
        { "id": "team_a", "name": "队伍A", "seats": [0] },
        { "id": "team_b", "name": "队伍B", "seats": [1] },
        { "id": "team_c", "name": "队伍C", "seats": [2] }
      ]
    },
    {
      "id": "board_2v2",
      "name": "双人组队",
      "player_count": 4,
      "teams": [
        { "id": "team_a", "name": "队伍A", "seats": [0, 2] },
        { "id": "team_b", "name": "队伍B", "seats": [1, 3] }
      ]
    }
  ]
}
```

字段规范：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | 是 | 唯一标识 |
| `name` | 是 | 显示名 |
| `player_count` | 是 | 座位总数，决定建多少玩家 |
| `teams[].id` | 是 | 队伍标识，写入 `PlayerData.team_id` |
| `teams[].name` | 是 | 显示名（「队伍A」） |
| `teams[].seats` | 是 | 该队占用的座位下标数组 |
| `default` | 否 | 缺省板子；无标记时取数组第一项 |
| `character_pool` | 否 | 角色池（本期留空表示全部角色可用） |
| `deck_composition` | 否 | 卡池覆盖（本期留空表示用 `cards.json`） |

校验规则（加载时执行，失败则报错并回退到 `board_1v1`）：

- `seats` 并集必须恰好等于 `0..player_count-1`，无重复、无越界。
- `teams` 非空，且每队至少 1 个座位。
- 所有 `team.id` 唯一。
- 座次只定义「哪个座位属于哪队」，**不绑定具体玩家**；运行时角色随机落座（见 4.3）。

### 4.2 `PlayerData` 扩展

```gdscript
var team_id: String = ""      # 所属队伍（来自板子）
var seat_index: int = 0       # 座位序号，等于 players 数组下标
```

约定：

- `seat_index` 与 `players` 下标恒等，禁止两者分叉。
- `seat_index` 由随机落座产生（见 4.3），不等于选人顺序。
- 单队模式（1v1v1）下 `team_id` 仍各自唯一，不要留空。
- 新增显示名辅助：`func display_name() -> String`，格式 `玩家N·角色名`；队伍信息由 UI 拼装，不写进 `name`。

### 4.3 座次与回合推进

- **随机落座**：选人完成后，把「所选角色」列表打乱后依次填入座位 0..N-1；随后按下标回写 `seat_index`，并按板子的 `seats` 映射写入 `team_id`。
  - 2v2 交错座位（0/2 vs 1/3）下，队友组合因此也是随机的。
  - 随机必须是**一次**打乱，不得在回合中再次重排；同一局内座次固定。
- **先手**：在座位范围内随机一人（沿用规则 4.1「随机确定先手」），不强制队伍交替。
- `_advance_player()` 保持「下标 +1 取模」的循环语义，仅在遇到 `dead` 时跳过，并保留现有 `guard` 上限。
- 追加一条保护：若一整圈没有任何存活玩家，直接进入 `GAME_OVER`（平局），不得死循环。
- 「跳过」状态的处理改为**循环**而非递归：在 `_prepare_turn()` 内用 `while` 推进，最多 `players.size()` 次，超过则视为全员跳过、进入终局判定。

### 4.4 目标类型语义（核心变更）

`_target_candidates(target_type, card_id)` 的语义重定义如下（`S` = 行动来源）：

| target_type | 1v1（兼容） | 1v1v1 | 2v2 |
| --- | --- | --- | --- |
| `none` / `self` | 自己 | 自己 | 自己 |
| `single_any` | 任意存活 | 任意存活 | 任意存活 |
| `single_enemy` | 对方 | 除自己外全部 | **任一其他存活玩家（含队友）** |
| `self_or_dying` | 自己 / 濒死者 | 自己 / 濒死者 | 自己 / 濒死者 |
| `all_players` | 双方 | 全员 | 全员 |
| `all_enemies` | 除自己外全员 | 除自己外全员 | **非同队**存活 |
| `all_allies` | 仅自己 | 仅自己 | **同队含自己** |
| `all_others` | 除自己外全员 | 除自己外全员 | 除自己外全员（含队友） |

关键点：

0. **口径 2.5-7 优先**：现有 `cards.json` / `skills.json` 中没有任何「敌人 / 敌方」措辞，描述统一为「目标」「一名其他玩家」，因此 `single_enemy` 在 2v2 下**包含队友**，只排除自己；队伍过滤只发生在 `all_enemies`。若未来出现明确点名单体敌人的卡牌，再新增 `single_hostile` 类型，不要改现有语义。
1. `all_enemies` 与 `all_others` 在 2v2 下**不再是同一个集合**，必须拆开。
2. `all_allies` 从「仅自己」升级为「同队含自己」；1v1 与 1v1v1 下行为不变，因此现有数据无需修改（当前 `data/` 中仅 `events.json` 的『天罚』使用 `all_players`，没有 `all_allies` 数据）。
3. 必须把「行动来源」从隐式 `current` 改为显式参数：`_target_candidates(tt, card_id, source_idx)`。`source` 属于 `pending` 的场景（濒死救援、放逐、事件）目前会取错人。
4. 为不破坏现有测试与调用方，保留旧签名 `_target_candidates(tt, card_id)` 作为包装（内部传 `current`），新代码一律走三参数版本。

### 4.5 胜负判定

```gdscript
func _check_deaths() -> void:
    # 1. 收集存活队伍
    # 2. 若存活队伍数 == 1 → 该队获胜
    # 3. 若 == 0 → 平局（winner 置空，UI 显示「同归于尽」）
    # 4. 否则继续
```

- 保持 `winner: String` 字段不变（供旧 UI/测试读取），新增：
  - `winner_team_id: String`
  - `winner_team_name: String`
  - `winner_members: Array[String]`（成员显示名）
- `winner` 在单队模式填成员名，在组队模式填队伍名（`winner_team_name`）。
- 终局日志改为「队伍A 获胜（玩家1·某角色、玩家3·某角色）」。
- `dev_win(idx)` 保留（开发者菜单用），在队伍模式下应改为按该玩家所属队伍获胜。

### 4.6 陷阱与行为事件的归属过滤

- `_emit_behavior()` 中，队友的陷阱不应因本方行为触发。
- 实现：追加 `if players[i].team_id == players[actor_idx].team_id: continue`；随后再判断 `i == actor_idx`。
- **可见性（口径 2.5-2）**：陷阱区 UI 中，队友的陷阱内容**全部可见**（与手牌公开程度一致）；敌方仍只见数量。

### 4.7 询问类窗口（〖放逐〗等）

- 口径 2.5-3：询问对象为**全部存活玩家**（含敌方），不按队伍过滤。
- 询问本身**不改变**技能目标合法性：即使某玩家被询问过，其目标资格仍只由 `single_enemy` / `single_any` 等队伍语义决定。
- 因此 `_has_skill(p, "skill_exile")` 的触发条件（技能持有者、限定次数）保持不动，只调整「轮到谁被询问」的遍历范围。
